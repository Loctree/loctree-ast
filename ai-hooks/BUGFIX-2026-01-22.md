# Bug Report: Hook Stability Fixes

**Date:** 2026-01-22
**Severity:** Medium
**Affects:** `loct-grep-augment.sh`, `loct-smart-suggest.sh`, `memex-startup.sh`

---

## Summary

Five stability issues were identified and fixed in the Claude Code hooks for Codex-POC readiness:

1. **Missing `jq` dependency check** - hooks would fail with errors instead of gracefully exiting
2. **Unbounded payload size** - large `loct find` outputs could cause client truncation/timeout
3. **No response deduplication** - repeated queries spammed identical context
4. **Inconsistent repo-root detection** - subfolder execution caused wrong project detection
5. **No debug logging** - difficult to diagnose issues in Codex wrappers

---

## Issue 1: Missing `jq` Dependency Check

### Problem

The `loct-grep-augment.sh` hook checked for `loct` CLI availability but not for `jq`, which is used extensively for JSON parsing and escaping.

```bash
# Before (incomplete)
command -v loct >/dev/null 2>&1 || exit 0
# jq used on line 37, 50, 51, 64, 104, 130, 198... but never checked!
```

### Impact

On systems without `jq` installed:
- Hook would pass the `loct` check
- First `jq` call would fail with `jq: command not found`
- Error output could confuse Claude Code or pollute logs

### Fix

Added explicit `jq` check after `loct` check:

```bash
# After (complete)
command -v loct >/dev/null 2>&1 || exit 0
command -v jq   >/dev/null 2>&1 || exit 0
```

### Affected Files

- `ai-hooks/loct-grep-augment.sh` - was missing check
- `ai-hooks/loct-smart-suggest.sh` - was missing check (had grep fallback but inconsistent)

## Issue 2: Unbounded Payload Size

### Problem

The `output_json()` function in `loct-grep-augment.sh` had no size limit on the `additionalContext` payload sent to Claude Code.

```bash
# Before (no limit)
local msg="..."
escaped=$(echo "$msg" | jq -Rs .)
# Could be 50KB+ for popular symbols!
```

### Impact

For queries matching many symbols (e.g., common utility functions):
- `loct find` could return 50KB+ of matches
- Large payloads cause client-side issues:
  - Slow JSON parsing
  - UI truncation without warning
  - Potential timeout or silent failure

### Fix

Added 32KB hard limit with informative truncation message:

```bash
# After (bounded)
MAX_PAYLOAD_BYTES=32768

truncate_payload() {
    local text="$1"
    local max="$2"
    if [[ ${#text} -gt $max ]]; then
        printf '%s\n\n[...truncated, showing first %d bytes of %d total]' \
            "${text:0:$max}" "$max" "${#text}"
    else
        printf '%s' "$text"
    fi
}

# In output_json():
msg="$(truncate_payload "$msg" "$MAX_PAYLOAD_BYTES")"
```

### Why 32KB?

- Safe limit for Claude Code hook system
- Preserves most useful context (symbol definitions, top matches)
- User sees truncation notice if limit hit
- Matches limit used in `loctree-plugin` reference implementation

### Affected Files

- `ai-hooks/loct-grep-augment.sh`

## Issue 3: No Response Deduplication (Spam)

### Problem

When user runs the same search multiple times (e.g., 10× `rg ThemeContext`), the hook would:
- Re-execute `loct find` every time (~75ms each)
- Return identical context 10 times
- Waste compute and potentially confuse the AI with repeated information

### Impact

- Unnecessary latency on repeated queries
- Context spam in conversation
- No benefit from caching previous work

### Fix

Added response cache with 60-second TTL:

```bash
CACHE_DIR="/tmp/.loct-grep-cache"
CACHE_TTL=60  # seconds

# Cache key: repo_root + git_commit + pattern + path
compute_cache_key() {
    local hash
    hash=$(printf '%s:%s:%s:%s' "$repo" "$commit" "$pattern" "$path" | md5)
    echo "${CACHE_DIR}/${hash}.json"
}

# On cache hit: return cached JSON (not silence!)
check_cache() {
    [[ -f "$cache_file" ]] && [[ $cache_age -lt $CACHE_TTL ]] && cat "$cache_file"
}
```

### Key Design Decision

**Cache returns response, not silence.** If we just `exit 0` on cache hit, Claude/Codex loses context. Instead, cached JSON is output so AI always gets augmentation.

### Platform Notes

- **macOS:** uses `md5` command (outputs hash directly)
- **Linux:** fallback to `md5sum | cut -c1-32` (different output format)
- Cache hit debug message goes to log file only (gated by `LOG_FILE`), not stderr

### Affected Files

- `ai-hooks/loct-grep-augment.sh`

## Issue 4: Inconsistent Repo-Root Detection

### Problem

`memex-startup.sh` used `$PWD` directly for:
- Cache key computation
- Project name detection

When user is in a subfolder (e.g., `~/project/src/components/`), this caused:
- Different cache keys for same project
- Wrong project name sent to memex search

### Impact

- Cache misses when navigating subfolders
- Memex queries for wrong project name
- Inconsistent behavior in Codex wrappers that may start in subdirectories

### Fix

Added repo-root discovery (same pattern as `loct-grep-augment.sh`):

```bash
# Find repo root (git root or .loctree parent)
REPO_ROOT=$(pwd)
GIT_ROOT=$(git rev-parse --show-toplevel 2>/dev/null || true)
if [[ -n "$GIT_ROOT" ]]; then
    REPO_ROOT="$GIT_ROOT"
else
    # Fallback: find .loctree directory
    while [[ "$REPO_ROOT" != "/" ]] && [[ ! -d "$REPO_ROOT/.loctree" ]]; do
        REPO_ROOT=$(dirname "$REPO_ROOT")
    done
fi

# Cache and project name now use REPO_ROOT
CACHE_FILE="/tmp/memex-startup-$(echo "$REPO_ROOT" | md5).cache"
PROJECT_NAME=$(basename "$REPO_ROOT")
```

### Fallback Behavior

If neither git root nor `.loctree` directory is found (e.g., in a random directory outside any project), the hook falls back to `$PWD`. This is intentional - better to work with current directory than fail.

### Affected Files

- `ai-hooks/memex-startup.sh`

## Issue 5: No Debug Logging

### Problem

When hooks misbehave in Codex wrappers or production, there was no way to diagnose:
- What patterns triggered which actions
- How long operations took
- Whether cache was hit or missed

### Impact

- Blind debugging
- No performance visibility
- Hard to reproduce issues

### Fix

Added optional logging (default OFF for security):

```bash
# Enable: export LOCT_HOOK_LOG_FILE="$HOME/.claude/logs/loct-grep.log"
LOG_FILE="${LOCT_HOOK_LOG_FILE:-}"

log_meta() {
    [[ -z "$LOG_FILE" ]] && return 0
    printf '%s\n' "$*" >> "$LOG_FILE"
}

log_end() {
    # Only logs metadata - NEVER tool_response!
    log_meta "pattern: ${pattern_short}"  # truncated to 40 chars
    log_meta "action:  $action"
    log_meta "time:    ${duration_ms}ms"
}
```

### Security

- **Default OFF** - no logging unless explicitly enabled
- **Metadata only** - logs pattern (truncated to 40 chars), path, action, timing
- **Never logs `tool_response`** - no risk of leaking code/secrets
- **Pattern truncation matters** - users sometimes grep for tokens/secrets; truncating to 40 chars + default OFF mitigates accidental exposure

### Affected Files

- `ai-hooks/loct-grep-augment.sh`
