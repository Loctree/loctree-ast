# v0.10.5 Yank Postmortem

Status: yanked locally, registry action pending operator execution
Date: 2026-05-27
Replacement: 0.11.0

## Summary

`0.10.5` is treated as yanked because it did not give agents a strong enough
runtime proof that the installed MCP server, context snapshot, and atlas scope
were all current after reinstall/restart churn. The failure mode was not "no
context"; it was worse: an agent could see a plausible but falsely narrow or
stale context surface and proceed with misplaced confidence.

`0.11.0` is the replacement line. Fresh evidence from the reinstalled
`loctree-mcp` and the new snapshot shows the command deck and context-atlas
contract back on the expected suite-wide footing.

## Impact

- Agents could trust a context pack that was too small for the real
  `loctree-suite` tree.
- MCP "transport closed" reports were noisy enough that checkout/version truth
  needed to be proven from the installed command deck, not inferred from source.
- Release confidence for `0.10.5` was therefore below the bar for agent-facing
  context delivery.

## Evidence

- Fresh `loct auto` on `fix/the-truth-of-findings@b09286f6` scanned 474 files in
  8.04s and generated a six-card Context Atlas.
- Installed `loctree-mcp --version` reports `0.11.0`.
- Raw MCP `tools/list` exposed 10 tools: `context`, `find`, `focus`, `follow`,
  `impact`, `prism`, `repo-view`, `slice`, `suppressions`, `tree`.
- MCP `context` returned a complete `loctree.context_atlas.v1` receipt with
  snapshot fingerprinting, branch `fix/the-truth-of-findings`, commit
  `b09286f6`, schema `0.11.0`, and the atlas sections loaded.
- MCP `repo_view` reported the atlas as available and matching the current
  snapshot, with 530 files, 632 edges, zero cycles, and zero dead exports.
- The fresh full context artifact
  `loct-v0-11-0-context-full.json` is 8,486 lines / 275,081 bytes and records
  commit `b09286f6`.

## Root Cause Hypothesis

The practical root cause was a proof gap around context freshness and MCP
install state, not a confirmed deterministic analyzer crash. Before the fresh
scan/reinstall proof, the agent-side surface could confuse an old or
scope-mismatched snapshot with current repository truth. That is unacceptable
for a context tool whose job is to prevent exactly this class of false certainty.

## Corrective Actions

- Mark `0.10.5` as yanked in the local release surfaces.
- Use `0.11.0` as the minimum trusted line for current MCP context work.
- Keep the context receipt visible in agent workflows: snapshot fingerprint,
  commit, branch, schema version, atlas sections loaded, and staleness state.
- Treat "transport closed" as an incident signal until installed-binary truth,
  MCP command deck, and fresh atlas state are all verified.
- Add release-gate coverage that proves the installed MCP server and `loct`
  snapshot agree after reinstall, not only that source tests pass.

registry mutation still needs the operator-owned credentials step:
